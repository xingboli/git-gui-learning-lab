# Git GUI：什么时候做什么

这份表先回答“现在该做什么”，再告诉你在 VS Code 或 GitHub 哪里操作。

## 日常决策表

| 现在的情况 | 应该做什么 | 为什么 | 去哪里确认 |
| --- | --- | --- | --- |
| 准备开始新任务 | 先同步 `main`，再创建分支 | 避免从旧版本开始工作 | VS Code 左下角分支名、源代码管理的同步状态 |
| 完成了一个可以独立说明的修改 | 检查差异、暂存相关文件、提交 | 提交应该表达一个目的 | **源代码管理 / Source Control** 的 Changes 与 Staged Changes |
| 同一文件包含两个目的 | 只暂存相关文件或代码块，分两次提交 | 以后更容易审查和撤销 | 点击文件查看差异；使用行内 `+` 暂存选中范围 |
| 功能还没完成但需要换任务 | 保留在功能分支；必要时用 Stash | 不把半成品混入 `main` | 源代码管理 `…` → **Stash / 贮藏** |
| 本地分支首次需要分享 | 发布分支 | GitHub 才能创建 PR 和运行检查 | **Publish Branch / 发布分支**，随后看 GitHub 分支页 |
| 分支已准备合并 | 创建 PR | 集中解释、检查、讨论和自动测试 | GitHub **Pull requests** → **New pull request** |
| PR 显示落后于 `main` | 先更新本地 `main`，再把它合入功能分支 | 提前处理集成问题 | VS Code 分支菜单与合并编辑器 |
| 两边修改同一位置 | 解决冲突并重新验证 | Git 无法替你决定业务上的正确结果 | VS Code **Merge Editor / 合并编辑器** |
| 未提交修改写错了 | 丢弃该文件或代码块 | 还没有公共历史，不需要新提交 | Changes 中右键 → **Discard Changes / 放弃更改** |
| 已暂存但还不想提交 | 取消暂存 | 修改仍保留，只从本次提交中移出 | Staged Changes 中点击 `-` |
| 本地提交还没分享且只是提交说明不完整 | 可谨慎使用 Amend | 尚未影响别人，可修正最后一次提交 | 源代码管理 `…` → **Commit** → **Commit Staged (Amend)** |
| 错误已经进入共享分支 | 创建 revert 提交或 Revert PR | 保留事实历史，避免强制改写别人已获取的提交 | 已合并 PR 的 **Revert** 按钮 |
| 测试通过且当前 `main` 值得被引用 | 创建版本标签和 Release | 给用户一个稳定、可说明的版本点 | GitHub **Releases** → **Draft a new release** |

## 提交、分支、PR、发布的边界

### 什么时候提交

当一个修改能用一句“动词 + 对象”说明并且项目仍可验证时提交。例如：

- `feat: add progress state model`
- `test: cover progress and storage behavior`
- `docs: explain recovery workflow`

不要用“改了一些东西”“最终版”作为提交信息。提交描述的是变化，不是心情或时间。

### 什么时候创建分支

只要工作可能需要多个提交、一次讨论或独立撤销，就从最新 `main` 创建分支。推荐格式：

- `feature/功能名`
- `fix/问题名`
- `docs/主题`
- `ci/自动化目标`

一个分支只服务一个明确目标。PR 合并后删除分支，下一个任务重新从最新 `main` 开始。

### 什么时候创建 PR

满足以下条件再创建 PR：

- 分支已经发布到 GitHub。
- 修改范围与 Issue 一致。
- 自己已经读过完整差异。
- 测试或手工验证已经完成。
- PR 描述能回答“为什么、改了什么、如何验证”。

### 什么时候发布版本

发布不是“代码刚写完”，而是：

- 目标功能已进入 `main`。
- 自动化检查全部成功。
- Pages 或交付物已验证。
- README 与变更日志反映实际结果。
- 版本号能够表达兼容关系。

本项目首次稳定发布使用 `v1.0.0`。修复兼容问题用 `v1.0.1`，向后兼容的新功能用 `v1.1.0`，破坏兼容性的更改才使用 `v2.0.0`。

## 三条安全原则

1. 操作前先看当前分支和差异，不凭记忆判断。
2. 已共享的历史用新提交纠正，不强制改写。
3. “合并成功”不等于“发布成功”，还要检查 Actions 和线上结果。
